# 오탐률(False Positive Rate) 테스트 케이스 설계

## 1. 목적
RaceGrader가 **실제로는 문제 없는(정상 동기화된) 커널 코드**를 race condition으로
잘못 판정(FAIL/PANIC)하는 비율을 측정하고, 허용 가능한 수준으로 낮춘다.

> 오탐(False Positive) = 정답(정상 동기화) 코드인데 FAIL/PANIC/TIMEOUT이 뜬 경우
> 오탐률 = 오탐 발생 횟수 / 전체 정상 케이스 실행 횟수 × 100%

## 2. 전제 조건 및 현재 상태 (2026-08-11 기준)
- 로그 형식 확정됨 (PR #9, #11 반영):
  - 실패: `[RACEGRADER_FAIL] ASSERT|file:line|SEED|PID|label`
  - 전체 통과: `[RACEGRADER_DONE] SEED|PID`
- ✅ **PR #5(교란 엔진) merge 완료** — 3.2 테스트 실행 가능
  - 실행 커맨드: `make qemu CPUS=2 SEED=<값> CHAOS=1`
  - 메커니즘: CPU별 독립 xorshift32 PRNG, 락 경계(acquire/release) 확률적 지연,
    scheduler() 매 라운드 proc 스캔 순서 Fisher-Yates 셔플
  - 인터럽트 켜진 상태에서만 훅 동작 → 자체 데드락 위험 없음
- `cow_test.c`: 정상(baseline) 버전 6개 체크포인트 포함, 이미 동작 확인됨 → 3.1/3.2 baseline 재료로 사용 가능
- ✅ **`mkfs` 빌드 블로커 해소** (이슈 #17 → PR merge) — `.gitignore` 수정으로 `mkfs.c`가 git에 정상 포함됨, `make qemu` 정상 동작 확인
- ✅ **3.3 블로커 해소** — `CHAOS_PROB_PERCENT`, `CHAOS_MAX_SPIN`이 make 변수로 노출됨 (기본값 30/2000 유지)
- ✅ **`CHAOS=0` 컴파일 에러 해소** (이슈 #24 → PR `fix/chaos-unused-when-disabled` merge) —
  `chaos_rand`/`chaos_spin` 정의를 `#if CHAOS_ENABLED`로 감싸 unused-function 에러 해결.
- ✅ **`main` 오염 복구 완료** (`fix/restore-clean-kalloc-on-main` merge) — `kalloc.c`가 정상 버전으로 복구됨.
  3.1a 재실행 가능해짐 (재실행 필요, 아래 4번 표 참고)
- ⚠️ **주의: `test/kernel-lock-missing`, `test/kernel-refcount-race`는 결함 버전(정탐/True Positive 테스트 대상)**
  — 오탐 테스트(본 문서)는 정상 동기화 코드(`cow_test.c`, `smp_check.c`)만 대상으로 함, 혼동 주의
- 🚨 **중요: `CPUS=8` 필수** — `CPUS=2`(기존 예시 커맨드)로는 경쟁 상황 자체가 잘 안 걸려서
  결함 커널로 돌려도 실패가 거의 안 잡힘. 최우주가 확인한 결함 커널 실측(1/500)도 전부
  `CPUS=8` 기준. **본 문서의 모든 CPUS=2 예시 커맨드는 CPUS=8로 교체 필요**
- N회 반복 실행 CLI 자동화는 최우주가 완료함 — 사용 커맨드 확정:
  ```
  go run . run --kernel ../kernel --command cow_test --repeat 500 --cpus 8 --timeout 60 --seed 0
  ```
- **파라미터 확정 (2026-08-25, 팀 확인 완료)**
  - 반복 횟수: **N=500** (최우주 추천 — 결함 커널 1/500 실측 기준, 그보다 적으면 "우연히 0건"인지 구분 불가)
  - SEED: **`--seed 0`(시간 기반 자동)** — 고정 범위보다 설득력 있음 (최우주 의견)
  - CPUS: **8** (필수)
  - 오탐률 허용 기준: **0% (500회 중 FAIL 0건 목표)** — 결함 커널 실측(0.2%, 500회 중 1건)보다
    명확히 낮아야 "탐지기가 정상 코드는 안 건드린다"는 주장이 설득력을 가짐. 1건이라도 나오면
    오탐이 아니라 원인 조사 대상으로 취급
  - 테스트 대상: `cow_test.c` 필수, **`smp_check.c`(2-way SMP 병렬성 검증용, 김수아가 오늘 작성)도
    시간 되면 추가** — 없어도 증명 자체는 충분하나 있으면 설득력 강화

## 3. 테스트 케이스 카테고리

### 3.1 정상 baseline
| 항목 | 내용 |
|---|---|
| 목적 | 최소 기준선 확인 |
| 3.1a — 진짜 무교란 baseline | `make qemu CPUS=8 CHAOS=0` — chaos.c 완전 비활성화, 100% PASS 기대 |
| 3.1b — 교란 켜진 단일 케이스 | `make qemu CPUS=8 CHAOS=1 SEED=1` — 교란 최소 검증용 단일 실행 |
| 대상 | 정상 동기화된 `cow_test.c` (+ 시간 되면 `smp_check.c`) |
| 반복 횟수 | 3.1a는 1회로 충분 (교란 없어 결과 고정), 3.1b는 실행만 확인용(1회) |
| 판정 | 3.1a가 100% PASS 아니면 CLI/파서 버그로 간주, 최우선 조사 |

### 3.2 정상 코드 + fault injection (핵심 오탐 테스트) — 파라미터 확정
| 항목 | 내용 |
|---|---|
| 목적 | 정상 동기화 코드(`cow_test.c`, 선택적으로 `smp_check.c`)가 반복 실행 하에서도 오탐 없이 통과하는지 확인 |
| 실행 커맨드 | `go run . run --kernel ../kernel --command cow_test --repeat 500 --cpus 8 --timeout 60 --seed 0` |
| 반복 횟수 | **N=500** |
| CPUS | **8 (필수 — CPUS=2로는 경쟁 상황이 거의 안 걸림)** |
| SEED | **0 (시간 기반 자동 생성)** |
| 판정 기준 | **오탐률 0% (500회 중 FAIL 0건)** — 1건이라도 나오면 오탐이 아니라 원인 조사 대상 |
| 자동화 | 최우주(CLI) 완료 — 바로 실행 가능 |
| 비고 | 이 카테고리가 QA 보고서의 핵심 지표. `smp_check.c`도 같은 조건으로 추가 실행 시 설득력 강화 |

### 3.3 경계 케이스 (TIMEOUT 임계값)
| 항목 | 내용 |
|---|---|
| 목적 | 정상 코드가 fault injection으로 느려졌을 때 TIMEOUT을 오탐으로 뱉지 않는지 확인 |
| 방법 | `make qemu CPUS=8 SEED=<값> CHAOS_MAX_SPIN=<값>` (필요시 `CHAOS_PROB_PERCENT=<값>`도 함께)로 지연 강도를 점진적으로 증가시키며 실행, TIMEOUT 발생 시점 기록 |
| 판정 | 설정된 TIMEOUT 임계값이 정상 실행 편차 대비 여유 있는지 검증 |
| 기본값 | `CHAOS_PROB_PERCENT=30`, `CHAOS_MAX_SPIN=2000` (옵션 미지정 시 기존 동작과 동일) |
| 상태 | ✅ 블로커 해소 (김수아 PR — make 변수로 노출 완료, 기본값 보존 확인됨) — 이제 진행 가능 |

### 3.4 로그 파싱 자체 오탐 (CLI 버그성 오탐)
| 항목 | 내용 |
|---|---|
| 목적 | 커널이 PASS를 뱉었는데 CLI 파서가 잘못 읽어 FAIL로 표시하는 경우 탐지 |
| 방법 | 로그 포맷 경계 케이스(중복 라인, 잘림, 순서 뒤바뀜 등) 인위적으로 넣고 파서 반응 확인 |
| 담당 | 최우주(CLI) 협업 필요 |
