### 2.2 핵심 기술 구현 (3주차)
- **로그 인터페이스 확정**
  - 실패: `[RACEGRADER_FAIL] ASSERT|file:line|SEED|PID|label`
  - 전체 통과: `[RACEGRADER_DONE] SEED|PID`
  - `panic()`(커널 크래시성 실패)과 `cow_test.c`의 `passfail()` 매크로(논리적 오류성 실패) 양쪽 다 반영 완료
- **스케줄링 교란 엔진(chaos engine) 구현**
  - CPU별 독립 xorshift32 PRNG로 락 경계(acquire/release)에 확률적 지연 주입
  - `scheduler()`의 매 라운드 proc 스캔 순서를 Fisher-Yates 셔플
  - 인터럽트 활성 상태에서만 동작하도록 설계해 자체 데드락 위험 없음
  - 실행: `make qemu CPUS=2 SEED=<값> CHAOS=1` (완전 비활성화는 `CHAOS=0`)
- **오탐률(False Positive Rate) 테스트 설계**
  - 정상 동기화 코드가 교란 하에서도 오판정(FAIL)되지 않는지 검증하는 체계 설계
  - baseline(무교란) → 교란 단일 케이스 → 반복 실행 기반 오탐률 측정 3단계로 구성
  - [TBD: 팀 미팅 후 확정된 오탐률 허용 기준(%), N(반복 횟수), SEED 선정 방식]
  - baseline(3.1a) 최초 실행 결과가 `main` 오염 상태에서 나온 것으로 확인되어 무효 처리,
    복구 후 재실행 대기 중 (섹션 5 리스크 참고)
- **결함 탐지 실증**
  - `test/kernel-refcount-race` 결함 커널을 500회 반복 실행해 정상 대비 대조 실험 진행
  - 희귀 레이스(500회 중 1회, 0.2%)를 실제로 재현 — 반복 실행 없이는 발견 불가능함을 실증
  - (단, 이 실험이 사용한 "정상(main)" 기준도 섹션 5의 main 오염 이슈로 재검증 필요)
